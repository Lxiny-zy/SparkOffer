# 大模型训练与微调

## 1. 预训练（Pre-training）

### 预训练目标
在海量无标注文本上学习语言的通用表示，获取世界知识和语言能力。

### 训练数据处理

#### 数据来源与规模
- 网页数据（Common Crawl）：万亿级 token
- 书籍（Books3, Gutenberg）：数百亿 token
- 代码（GitHub, Stack）：数百亿 token
- 论文（arXiv）、百科（Wikipedia）等
- LLaMA-3 训练数据量：15T+ tokens

#### 数据清洗流程
```
原始数据 → 语言检测（过滤非目标语言）
        → URL/HTML 清洗（去标签、广告）
        → 质量过滤（困惑度过滤、分类器过滤）
        → 去重（MinHash/SimHash 近似去重、精确去重）
        → 毒性过滤（安全分类器）
        → PII 脱敏（个人信息移除）
        → 混合配比（不同来源按比例混合）
```

#### 数据质量的重要性
- "Garbage in, garbage out"：数据质量直接决定模型质量
- 去重极其重要：重复数据会导致模型记忆而非泛化
- 数据配比影响能力分布：代码数据多则编程能力强

### Tokenizer（分词器）

#### BPE（Byte Pair Encoding）
- GPT 系列使用
- 流程：
  1. 将所有文本拆分为单个字符（初始词表）
  2. 统计相邻字符对的频率
  3. 将最高频的字符对合并为新 token
  4. 重复步骤 2-3 直到词表达到目标大小
- 示例：
  ```
  初始: ['l', 'o', 'w', 'e', 'r']
  统计: ('l','o')出现10次, ('o','w')出现8次, ('e','r')出现15次
  合并: 'er' → ['l', 'o', 'w', 'er']
  继续: 'lo' → ['lo', 'w', 'er']
  继续: 'low' → ['low', 'er']
  最终: ['lower']
  ```
- 词表大小：GPT-2 = 50257，LLaMA = 32000，Qwen-2.5 = 151643

#### SentencePiece
- Google 出品，语言无关的分词器
- 直接处理原始 Unicode 文本，不依赖空格分词
- 对中文、日文等非空格语言更友好
- LLaMA、Qwen 等使用
- 支持 BPE 和 Unigram 两种算法

#### Byte-Level BPE
- 将文本视为字节序列（UTF-8 编码）
- 基础词表只有 256 个字节
- 永远不会出现 OOV（Out of Vocabulary）
- GPT-2/3/4、LLaMA-3 使用

#### Tokenizer 对模型的影响
- 词表大小影响嵌入层参数量（vocab_size * d_model）
- 分词粒度影响序列长度（细粒度 = 更长序列 = 更多计算）
- 中文分词：如果词表中中文覆盖不够，会拆成更多 token，效率低

### 预训练任务

#### CLM（Causal Language Modeling）
- 预测下一个 token，GPT 系列使用
- Loss = -sum(log P(x_t | x_1, ..., x_{t-1}))
- 所有位置都参与 loss 计算，训练效率高
- **当前主流**

#### MLM（Masked Language Modeling）
- 随机 mask 15% 的 token，预测被 mask 的 token
- BERT 使用
- 只有 mask 位置参与 loss 计算，训练效率相对低

### 预训练计算成本

| 模型 | 参数量 | 训练 Token | GPU | 大约成本 |
|------|--------|-----------|-----|---------|
| GPT-3 | 175B | 300B | 1024x A100 | ~300 万美元 |
| LLaMA-2 70B | 70B | 2T | 2048x A100 | ~170 万 GPU 小时 |
| LLaMA-3 405B | 405B | 15T+ | 16384x H100 | ~数千万美元 |
| DeepSeek-V3 | 671B MoE | 14.8T | 2048x H800 | ~557 万美元 |

### Scaling Law
- Kaplan et al. (2020)、Chinchilla (2022) 提出
- 模型性能（loss）与模型参数量 N、数据量 D、计算量 C 呈幂律关系
- Chinchilla 最优：训练 token 数应约为参数量的 20 倍
  - 10B 模型 → 200B tokens
  - 70B 模型 → 1.4T tokens
- 指导了模型大小和训练数据量的选择

## 2. 监督微调（SFT - Supervised Fine-Tuning）

### 目标
让预训练模型学会遵循指令、对话格式、输出规范，变成一个有用的助手。

### 数据格式
```json
{
  "messages": [
    {"role": "system", "content": "你是一个专业的技术助手。"},
    {"role": "user", "content": "解释什么是 TCP 三次握手"},
    {"role": "assistant", "content": "TCP 三次握手是建立 TCP 连接的过程..."}
  ]
}
```

### SFT 数据要求
- 规模：通常 1 万-100 万条高质量指令对
- 质量 > 数量：LIMA 论文证明 1000 条高质量数据就能显著提升
- 多样性：覆盖不同任务类型（问答、写作、代码、推理等）
- 数据来源：
  - 人工标注（质量最高，成本高）
  - GPT-4/Claude 生成（Self-Instruct、Evol-Instruct）
  - 开源数据集（OpenAssistant、ShareGPT、Alpaca）

### SFT 训练细节
- 通常只训练 1-5 个 epoch（防止过拟合）
- 学习率较小（1e-5 ~ 5e-5）
- **只对 assistant 部分计算 loss**（不对 system 和 user 部分计算 loss）
- 使用 Packing 技术：将多条短数据拼接到一条，提高训练效率
- Chat Template：每个模型有自己的对话模板格式

### SFT 的局限
- 只学习"模仿"标注数据，不能学习偏好
- 无法区分"好回答"和"坏回答"
- 需要对齐技术进一步优化

## 3. 对齐技术（Alignment）

### RLHF（Reinforcement Learning from Human Feedback）

OpenAI 在 InstructGPT 中提出的方法：

#### Step 1：收集人类偏好数据
- 给模型同一个 prompt，生成多个回答（如 4 个）
- 人类标注员对回答排序（哪个更好）
- 构建偏好对：(prompt, chosen, rejected)

#### Step 2：训练奖励模型（Reward Model）
```
输入: prompt + response
输出: 标量分数（质量评分）

Loss = -log(sigmoid(r(chosen) - r(rejected)))
```
- Bradley-Terry 模型：将排序转化为 pairwise comparison
- 奖励模型通常基于 SFT 模型初始化（去掉最后一层，加一个标量输出头）

#### Step 3：PPO 强化学习优化
```
目标: max E[R(prompt, response)] - beta * KL(pi || pi_ref)

其中:
  R = 奖励模型的打分
  KL = 当前策略与参考策略的 KL 散度（防止偏离太远）
  beta = KL 惩罚系数
```
- 需要同时维护 4 个模型：Actor, Critic, Reward Model, Reference Model
- 训练不稳定，超参数敏感，工程复杂

### DPO（Direct Preference Optimization）

2023 年提出，大幅简化 RLHF 流程：

```
Loss = -log sigmoid(beta * (log pi(chosen|x)/pi_ref(chosen|x)
                           - log pi(rejected|x)/pi_ref(rejected|x)))
```

**核心思想**：
- 推导证明：最优策略可以直接从偏好数据中学习，无需单独训练 Reward Model
- 将 RLHF 的 RL 优化问题转化为一个简单的二分类损失
- 只需要偏好数据和参考模型

**DPO vs RLHF**：

| 维度 | RLHF | DPO |
|------|------|-----|
| 复杂度 | 高（4 个模型） | 低（2 个模型） |
| 训练稳定性 | 不稳定 | 稳定 |
| 超参数 | 多，敏感 | 少，鲁棒 |
| 效果 | 好 | 可比，部分场景更好 |
| 工程成本 | 高 | 低 |

**DPO 变体**：
- **IPO（Identity Preference Optimization）**：修正 DPO 的过拟合问题
- **KTO（Kahneman-Tversky Optimization）**：不需要成对偏好数据，只需要好/坏标签
- **ORPO（Odds Ratio Preference Optimization）**：不需要参考模型，直接在 SFT 过程中对齐
- **SimPO**：简化版 DPO，使用序列平均 log 概率作为隐式奖励

### GRPO（Group Relative Policy Optimization）

DeepSeek 提出的方法，用于 DeepSeek-R1 的训练：

```
流程:
1. 对每个 prompt 采样 G 个回答（如 G=64）
2. 用规则/验证器（如数学验证）给每个回答打分
3. 组内标准化分数作为 advantage
4. 用 advantage 更新策略

优势:
- 不需要 Reward Model（用规则/验证器替代）
- 组内相对排序，更稳定
- 特别适合有明确验证标准的任务（数学、代码）
```

### 对齐技术总结

| 方法 | 需要 RM | 训练方式 | 复杂度 | 代表应用 |
|------|--------|---------|--------|---------|
| RLHF/PPO | 是 | RL | 高 | ChatGPT, Claude |
| DPO | 否 | 分类 loss | 低 | Zephyr, Intel NeuralChat |
| GRPO | 否 | 组内相对 | 中 | DeepSeek-R1 |
| KTO | 否 | 单标签 | 低 | 开源模型 |
| ORPO | 否 | SFT+对齐 | 低 | 开源模型 |

## 4. 参数高效微调（PEFT）

### 为什么需要 PEFT
- 全量微调 7B 模型需要约 28GB 显存（FP32），更大模型更不可行
- 7B 模型全量微调需要存储：模型参数 + 梯度 + 优化器状态 ≈ 28 * 4 = 112 GB
- PEFT 只训练极少量参数（通常 < 1%），效果接近全量微调

### LoRA（Low-Rank Adaptation）

最流行的 PEFT 方法。

**核心思想**：
- 权重更新矩阵 delta_W 是低秩的：delta_W = B * A
- 冻结原始模型权重 W，只训练 A 和 B
- A（d x r）和 B（r x d），r << d

```
原始：h = Wx
LoRA：h = Wx + BAx    (W 冻结，只训练 B 和 A)

初始化：
  A ~ N(0, sigma^2)  （高斯初始化或 Kaiming 初始化）
  B = 0               （零初始化，训练开始时 LoRA 输出为 0）

缩放：
  h = Wx + (alpha/r) * BAx
  alpha 是缩放因子，通常设为 r 的 1-2 倍

参数对比（以 d=4096, r=16 为例）：
  原始参数：4096 * 4096 = 16,777,216
  LoRA 参数：4096 * 16 + 16 * 4096 = 131,072（仅 0.78%）
```

**关键超参数**：
- **r（秩）**：通常 8-64，越大表达能力越强但参数越多
  - 简单任务（分类）：r=8 通常够用
  - 复杂任务（指令微调）：r=32-64
- **alpha**：缩放因子，通常设为 r 的 1-2 倍
  - alpha/r 决定 LoRA 的"学习强度"
- **target_modules**：对哪些层应用 LoRA
  - 最小配置：q_proj, v_proj
  - 推荐：q_proj, k_proj, v_proj, o_proj（所有 attention 投影）
  - 全量：还包括 gate_proj, up_proj, down_proj（FFN 层）

**LoRA 使用示例**：
```python
from peft import LoraConfig, get_peft_model, TaskType

lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                     "gate_proj", "up_proj", "down_proj"],
    bias="none"
)

model = get_peft_model(base_model, lora_config)
model.print_trainable_parameters()
# 输出: trainable params: 13,107,200 || all params: 6,751,014,912 || trainable%: 0.194%
```

### QLoRA（Quantized LoRA）

先将模型量化到 4-bit（NF4），再用 LoRA 微调：

```
QLoRA 关键技术：
1. NF4（4-bit NormalFloat）量化
   - 基于正态分布的量化方式，信息损失最小
2. Double Quantization
   - 量化参数本身也被量化，进一步节省显存
3. Paged Optimizers
   - 优化器状态在 CPU/GPU 之间自动分页

显存对比（7B 模型微调）：
  全量微调（FP32）：~112 GB
  全量微调（BF16）：~56 GB
  LoRA（BF16）：~16 GB
  QLoRA（NF4）：~6 GB  ← 单卡 RTX 3090/4090 即可
```

```python
from transformers import BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    quantization_config=bnb_config,
    device_map="auto"
)
# 然后在量化模型上应用 LoRA
```

### 其他 LoRA 变体

| 变体 | 核心改进 | 优势 |
|------|---------|------|
| LoRA+ | A 和 B 使用不同学习率（B 的学习率更大） | 收敛更快 |
| DoRA | 将权重分解为方向和大小，分别用 LoRA | 效果更接近全量微调 |
| rsLoRA | 缩放因子 = alpha/sqrt(r) 而非 alpha/r | 大秩时更稳定 |
| AdaLoRA | 自适应调整不同层的秩 | 参数分配更优 |
| LoRA-FA | 冻结 A，只训练 B | 进一步减少显存 |

### Adapter

- 在 Transformer 每一层插入小型瓶颈网络（Bottleneck）
- 结构：Linear(d → r) → ReLU → Linear(r → d) + 残差连接
- 原始层冻结，只训练 Adapter 参数
- 比 LoRA 推理时多一点串行开销（LoRA 可以合并到原始权重）

### Prefix Tuning / P-Tuning v2

- 在每一层的输入前添加可学习的"虚拟 token"（前缀向量）
- 只训练这些前缀的嵌入（每层独立的前缀参数）
- 适合特定任务的适配，对模型权重完全不做修改
- P-Tuning v2 在每一层都加前缀，效果优于只在输入层加的 P-Tuning v1

### PEFT 方法对比

| 方法 | 可训练参数比 | 推理开销 | 效果 | 特点 |
|------|------------|---------|------|------|
| LoRA | ~0.1-1% | 无（可合并） | 最佳 | 最流行，推荐首选 |
| QLoRA | ~0.1-1% | 反量化开销 | 接近 LoRA | 显存极低 |
| Adapter | ~1-5% | 有（串行） | 好 | 模块化 |
| Prefix Tuning | ~0.1% | 增加前缀长度 | 一般 | 不改权重 |
| 全量微调 | 100% | 无 | 最佳 | 成本最高 |

## 5. 量化技术

### 量化基本原理
将浮点数映射为低精度整数，减少存储和计算开销：

```
量化公式:
  x_quant = round(x / scale + zero_point)
  x_dequant = (x_quant - zero_point) * scale

对称量化（zero_point = 0）:
  scale = max(|x|) / (2^(bits-1) - 1)

非对称量化:
  scale = (max(x) - min(x)) / (2^bits - 1)
  zero_point = round(-min(x) / scale)
```

### 量化方法对比

| 方法 | 精度 | 方式 | 说明 |
|------|------|------|------|
| FP32 | 32-bit | - | 原始精度，4 字节/参数 |
| FP16/BF16 | 16-bit | 训练时常用 | 2 字节/参数，BF16 动态范围更大 |
| INT8 | 8-bit | LLM.int8() | 1 字节/参数，精度损失小 |
| NF4 | 4-bit | QLoRA | 基于正态分布的量化 |
| GPTQ | 4-bit | 逐层量化 | 需要校准数据，基于 OBQ 算法 |
| AWQ | 4-bit | 保护重要通道 | 精度更好，无需校准数据 |
| GGUF | 多种(Q2-Q8) | llama.cpp | 支持 CPU 推理，格式灵活 |
| FP8 | 8-bit | 训练/推理 | H100 原生支持，DeepSeek-V3 使用 |

### GPTQ 详解
- 基于 OBQ（Optimal Brain Quantization）算法
- 逐层量化：一次量化一层的权重
- 需要少量校准数据（~128 条）来估计量化误差
- 量化后精度较好，GPU 推理速度快
- 适合 GPU 部署场景

### AWQ（Activation-aware Weight Quantization）
- 观察到：权重的重要性取决于其对应的激活值大小
- 保护与大激活值对应的权重通道（不量化或高精度量化）
- 相比 GPTQ 不需要校准数据
- 精度通常优于 GPTQ

### GGUF（llama.cpp 格式）
- 支持多种量化级别：Q2_K, Q3_K_M, Q4_K_M, Q5_K_M, Q6_K, Q8_0
- 支持 CPU + GPU 混合推理（offloading）
- 适合消费级硬件部署
- 命名规则：Q{bits}_K_{size}，如 Q4_K_M 表示 4-bit K-quant Medium

### 量化模型大小估算
```
7B 模型：
  FP32:  7 * 4  = 28 GB
  FP16:  7 * 2  = 14 GB
  INT8:  7 * 1  = 7 GB
  INT4:  7 * 0.5 = 3.5 GB

70B 模型：
  FP16:  70 * 2  = 140 GB（需要多卡）
  INT8:  70 * 1  = 70 GB（需要 1-2 张 A100 80GB）
  INT4:  70 * 0.5 = 35 GB（单卡 A100 80GB 可以跑）
```

## 6. MoE（Mixture of Experts）混合专家模型

### 核心思想
- 不是所有参数都激活，每个 token 只经过部分"专家"网络
- 总参数量大（模型容量大），但每个 token 的计算量小
- 以较低的推理成本获得更大模型容量的效果

### MoE 结构
```
标准 FFN:
  output = FFN(x)

MoE FFN:
  1. Router（路由器）计算每个专家的权重:
     gate_scores = softmax(W_gate * x)    # [num_experts]
  2. 选择 Top-K 个专家（通常 K=1 或 2）
  3. 加权组合专家输出:
     output = sum(gate_scores[i] * Expert_i(x))  for i in Top-K
```

### 路由策略
- **Top-K Routing**：选择得分最高的 K 个专家
- **Expert Choice**：每个专家选择 Top-K 个 token（反向路由）
- **负载均衡**：通过辅助 loss 防止所有 token 都路由到同一个专家
  ```
  Balance Loss = alpha * sum(f_i * P_i)
  f_i = 分配到专家 i 的 token 比例
  P_i = 路由到专家 i 的平均概率
  ```

### DeepSeek-V2/V3 MoE 架构

#### DeepSeek-V2 创新
- **细粒度专家**：160 个小专家（vs Mixtral 的 8 个大专家）
- **共享专家**：2 个共享专家处理所有 token（捕获通用知识）
- **每 token 激活 6 个专家** + 2 个共享专家
- 总参数 236B，激活参数 21B

#### DeepSeek-V3 架构
- 总参数 671B（MoE），每 token 激活 37B
- 256 个路由专家 + 1 个共享专家
- 每 token 激活 8 个路由专家 + 1 个共享专家
- **辅助无损负载均衡**：不使用辅助 loss（避免影响模型质量），而是用偏置项调节负载
- **FP8 混合精度训练**：首个成功用 FP8 训练的大规模 MoE 模型
- **Multi-Token Prediction (MTP)**：同时预测多个未来 token

#### Mixtral 8x7B（Mistral AI）
- 8 个专家，每次激活 2 个
- 每层独立路由
- 总参数 ~47B，激活参数 ~13B
- 效果接近 LLaMA-2 70B，但推理速度更快

### MoE 优缺点

| 优点 | 缺点 |
|------|------|
| 更大模型容量 | 显存占用大（需加载所有专家） |
| 推理计算量相对小 | 路由负载不均衡问题 |
| 可扩展性好 | 训练不稳定 |
| 性价比高 | 微调困难（专家坍缩） |

## 7. 分布式训练

### 数据并行（Data Parallelism, DP）
- 每张 GPU 持有完整模型副本
- 数据分成多份，每张 GPU 处理不同的 batch
- 梯度汇总（All-Reduce）后同步更新
- 瓶颈：模型必须能放入单卡显存

### 张量并行（Tensor Parallelism, TP）
- 将单个矩阵运算分到多张 GPU
- 如将 W 按列切分为 [W_1, W_2]，分配到两张 GPU
- 需要频繁通信（AllReduce），适合同一节点内的多 GPU
- vLLM: `--tensor-parallel-size N`

### 流水线并行（Pipeline Parallelism, PP）
- 不同层放在不同 GPU
- 如 32 层模型分到 4 张 GPU，每张 8 层
- 需要处理"气泡"（bubble）问题（某些 GPU 空闲等待）
- GPipe、PipeDream 等方案

### 3D 并行
- 结合 DP + TP + PP，大模型训练的标准配置
- 如 Megatron-LM：TP 在节点内（NVLink 高带宽），PP 在节点间

### DeepSpeed ZeRO
- **ZeRO-1**：分片优化器状态（16 字节/参数 → 4+12/N）
- **ZeRO-2**：分片优化器状态 + 梯度
- **ZeRO-3**：分片优化器状态 + 梯度 + 模型参数（等价于 FSDP）

### FSDP（Fully Sharded Data Parallelism）
- PyTorch 原生的分布式训练方案，类似 ZeRO-3
- 不需要额外安装 DeepSpeed
- PyTorch 2.x 中功能逐步完善

### 混合精度训练
```
FP32 Master Weights → FP16/BF16 Forward/Backward → FP32 Gradient Update

BF16 vs FP16:
  FP16: 精度高（10 位尾数），动态范围小 → 需要 loss scaling
  BF16: 精度低（7 位尾数），动态范围大 → 不需要 loss scaling，更稳定
  现代 LLM 训练首选 BF16
```

## 面试高频问题

### Q1: 大模型训练的三个阶段分别是什么？各自的作用？
**答**：预训练在海量无标注数据上学习通用语言能力和世界知识；SFT 用指令数据教会模型遵循指令和对话格式；对齐阶段（RLHF/DPO）通过人类偏好数据使模型输出符合人类价值观，减少有害输出。

### Q2: RLHF 的完整流程？DPO 相比 RLHF 的优势？
**答**：RLHF 三步：收集人类偏好数据 → 训练奖励模型 → PPO 强化学习优化策略模型。DPO 将 RL 优化目标转化为简单的分类损失，不需要单独训练 Reward Model，只需 2 个模型（vs RLHF 4 个），训练更稳定，超参数更少，工程复杂度大幅降低。

### Q3: LoRA 的原理？为什么有效？
**答**：LoRA 假设微调时的权重变化矩阵是低秩的，用两个小矩阵 B(d,r) 和 A(r,d) 的乘积近似，冻结原始权重只训练 B 和 A。有效原因：1) 微调的权重更新确实具有低秩特性；2) 低秩约束起到正则化效果；3) 训练初始 BA=0 不改变原始模型行为。

### Q4: QLoRA 如何实现低显存微调？
**答**：三个关键技术：NF4 量化（基于正态分布的 4-bit 量化）将模型权重从 FP16 压缩到 4-bit；Double Quantization 进一步量化量化参数本身；Paged Optimizers 在 CPU/GPU 间自动分页。7B 模型微调只需约 6GB 显存。

### Q5: GPTQ 和 AWQ 量化的区别？
**答**：GPTQ 基于 OBQ 算法逐层量化权重，需要少量校准数据，通过最小化量化误差来确定量化参数。AWQ 观察到权重重要性取决于激活值大小，优先保护大激活对应的权重通道，不需要校准数据，精度通常优于 GPTQ。

### Q6: MoE 的优势和挑战？
**答**：优势：更大模型容量但激活参数少，推理性价比高。挑战：全量显存占用大（需加载所有专家）、路由负载不均衡、训练不稳定、微调困难（专家坍缩）。DeepSeek-V3 通过共享专家、细粒度路由和无损负载均衡缓解了这些问题。

### Q7: 如何在单卡 24GB（如 RTX 4090）上微调大模型？
**答**：使用 QLoRA：4-bit 量化加载 7B 模型（约 4GB）+ LoRA 微调（额外约 2GB）+ 优化器状态和梯度（约 2-4GB），总计约 8-10GB。配合 gradient checkpointing 和 gradient accumulation 进一步节省显存。

### Q8: BPE 分词的原理？对模型有什么影响？
**答**：BPE 从字符级开始，反复合并最高频字符对，构建词表。影响包括：词表大小决定嵌入层参数量；分词粒度影响序列长度和计算量；对中文等非空格语言，如果词表覆盖不够会产生过多 token，降低效率和效果。SentencePiece 在语言无关性上更好。

### Q9: Scaling Law 的核心结论？对训练有什么指导意义？
**答**：模型 loss 与参数量 N、数据量 D、计算量 C 呈幂律关系。Chinchilla 最优规则指出训练 token 数应约为参数量的 20 倍。这指导了预训练时的模型大小和数据量选择，避免"模型太大数据不够"或"数据够多模型太小"的浪费。

### Q10: DeepSeek-V3 有哪些关键创新？
**答**：1) MLA 替代 GQA 实现更高效的 KV Cache 压缩；2) 细粒度 MoE（256 路由专家+1 共享专家）；3) 辅助无损负载均衡（不用辅助 loss）；4) FP8 混合精度训练；5) Multi-Token Prediction。以较低成本（约 557 万美元）训练出与 GPT-4 级别可比的模型。
