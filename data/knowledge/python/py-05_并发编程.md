# Python 并发编程

## GIL（全局解释器锁）

### 什么是 GIL

- GIL（Global Interpreter Lock）是 CPython 解释器中的全局互斥锁
- 同一时刻只允许一个线程执行 Python 字节码
- 目的：保护 CPython 的内存管理（引用计数）不受竞态条件影响
- GIL 是 CPython 的实现细节，不是 Python 语言规范的一部分

### GIL 的工作机制

```python
# GIL 的释放时机：
# 1. I/O 操作（文件读写、网络请求、sleep）
# 2. 执行 C 扩展中标记为"释放 GIL"的代码（如 numpy 运算）
# 3. Python 3.2+：每执行 5ms（而非固定字节码条数）释放一次 GIL

# 验证 GIL 对 CPU 密集型任务的影响
import threading
import time

def cpu_bound(n):
    """CPU 密集型任务"""
    total = 0
    for i in range(n):
        total += i * i
    return total

# 单线程
start = time.time()
cpu_bound(10**7)
cpu_bound(10**7)
print(f"单线程: {time.time() - start:.2f}s")

# 多线程（因 GIL 不会更快，甚至可能更慢）
start = time.time()
t1 = threading.Thread(target=cpu_bound, args=(10**7,))
t2 = threading.Thread(target=cpu_bound, args=(10**7,))
t1.start(); t2.start()
t1.join(); t2.join()
print(f"多线程: {time.time() - start:.2f}s")
# 多线程可能比单线程更慢（线程切换开销 + GIL 竞争）
```

### 绕过 GIL 的方法

```python
# 方法1：使用多进程（每个进程有独立的 GIL）
from multiprocessing import Pool

# 方法2：使用 C 扩展，在 C 代码中释放 GIL
# 如 numpy, scipy, pandas 的底层运算

# 方法3：使用 ctypes/Cython 编写 C 扩展
# with nogil:  # Cython 语法
#     heavy_computation()

# 方法4：使用其他 Python 实现
# Jython（无 GIL）、PyPy（有 GIL 但 JIT 优化）

# 方法5：Python 3.12+ 的 subinterpreters
# Python 3.13+ 的实验性 free-threaded mode (--disable-gil)
# PEP 703: 使 GIL 可选（正在逐步推进）

# 方法6：使用 concurrent.futures 统一接口，方便在线程池/进程池间切换
from concurrent.futures import ProcessPoolExecutor
with ProcessPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(cpu_bound, [10**7]*4))
```

## 多线程 threading

### 基础用法

```python
import threading

# 方式1：传入目标函数
def worker(name, delay):
    print(f"线程 {name} 开始")
    import time
    time.sleep(delay)
    print(f"线程 {name} 结束")

t = threading.Thread(target=worker, args=("A", 1), daemon=False)
t.start()       # 启动线程
t.join()        # 等待线程结束
t.join(timeout=5)  # 最多等5秒
print(t.is_alive())  # 线程是否仍在运行

# 方式2：继承 Thread 类
class MyThread(threading.Thread):
    def __init__(self, name):
        super().__init__()
        self.name = name
        self.result = None

    def run(self):
        """重写 run 方法"""
        import time
        time.sleep(1)
        self.result = f"{self.name} 完成"

t = MyThread("Worker")
t.start()
t.join()
print(t.result)

# 守护线程（daemon）
# 主线程退出时，守护线程自动终止
t = threading.Thread(target=worker, args=("daemon", 10), daemon=True)
t.start()
# 主线程结束后，daemon 线程立即停止
```

### 线程同步原语

```python
import threading

# 1. Lock（互斥锁）
lock = threading.Lock()
counter = 0

def safe_increment():
    global counter
    with lock:  # 自动 acquire/release
        temp = counter
        temp += 1
        counter = temp

# 注意：Lock 不可重入，同一线程再次 acquire 会死锁
# lock.acquire()
# lock.acquire()  # 死锁！

# 2. RLock（可重入锁）
rlock = threading.RLock()

def recursive_func(n):
    with rlock:  # 同一线程可以多次 acquire
        if n > 0:
            recursive_func(n - 1)

# 3. Semaphore（信号量）：限制并发数
sem = threading.Semaphore(3)  # 最多3个线程同时执行

def limited_resource():
    with sem:
        print(f"{threading.current_thread().name} 获取资源")
        import time
        time.sleep(1)

# 4. Event（事件）：线程间通信
event = threading.Event()

def waiter():
    print("等待事件...")
    event.wait()      # 阻塞直到 event.set()
    print("事件发生！")

def setter():
    import time
    time.sleep(2)
    event.set()        # 触发事件

# 5. Condition（条件变量）：复杂的等待/通知
condition = threading.Condition()
queue = []

def producer():
    with condition:
        queue.append("item")
        condition.notify()  # 通知一个等待的线程

def consumer():
    with condition:
        while not queue:
            condition.wait()  # 释放锁并等待通知
        item = queue.pop()
        print(f"消费: {item}")

# 6. Barrier（屏障）：等所有线程到齐再继续
barrier = threading.Barrier(3)

def phase_worker(name):
    print(f"{name}: 阶段1完成")
    barrier.wait()  # 等其他线程
    print(f"{name}: 开始阶段2")
```

### 死锁与避免

```python
# 死锁示例
lock_a = threading.Lock()
lock_b = threading.Lock()

def thread_1():
    with lock_a:
        import time
        time.sleep(0.1)
        with lock_b:  # 等待 lock_b，但 thread_2 持有它
            pass

def thread_2():
    with lock_b:
        import time
        time.sleep(0.1)
        with lock_a:  # 等待 lock_a，但 thread_1 持有它
            pass

# 避免死锁的策略：
# 1. 锁排序：所有线程按相同顺序获取锁
def safe_thread_1():
    with lock_a:    # 先 A 后 B
        with lock_b:
            pass

def safe_thread_2():
    with lock_a:    # 先 A 后 B（同样顺序）
        with lock_b:
            pass

# 2. 超时机制
if lock_a.acquire(timeout=5):
    try:
        if lock_b.acquire(timeout=5):
            try:
                pass
            finally:
                lock_b.release()
    finally:
        lock_a.release()

# 3. 使用 contextlib.ExitStack 管理多个锁
```

## 多进程 multiprocessing

### 基础用法

```python
from multiprocessing import Process, Pool, Queue, Pipe, Manager
import os

# 基本进程创建
def worker(name):
    print(f"进程 {name}, PID={os.getpid()}, 父PID={os.getppid()}")

p = Process(target=worker, args=("子进程",))
p.start()
p.join()

# 进程池
def compute(n):
    return sum(i * i for i in range(n))

with Pool(processes=4) as pool:
    # map：阻塞，等所有结果
    results = pool.map(compute, [10**6, 10**6, 10**6, 10**6])

    # map_async：非阻塞
    async_result = pool.map_async(compute, [10**6]*4)
    results = async_result.get(timeout=10)

    # apply_async：单个任务非阻塞
    future = pool.apply_async(compute, (10**6,))
    result = future.get()

    # imap：惰性版 map，结果按顺序返回
    for result in pool.imap(compute, range(10)):
        print(result)

    # imap_unordered：惰性版，结果不保证顺序（更快）
    for result in pool.imap_unordered(compute, range(10)):
        print(result)

    # starmap：解包参数
    pool.starmap(func, [(1, 2), (3, 4)])  # 等价于 func(1, 2), func(3, 4)
```

### 进程间通信（IPC）

```python
# 1. Queue（进程安全队列）
from multiprocessing import Queue

def producer(q):
    for i in range(5):
        q.put(f"数据{i}")
    q.put(None)  # 结束信号

def consumer(q):
    while True:
        item = q.get()
        if item is None:
            break
        print(f"消费: {item}")

q = Queue()
Process(target=producer, args=(q,)).start()
Process(target=consumer, args=(q,)).start()

# 2. Pipe（管道，两个进程间通信）
parent_conn, child_conn = Pipe()

def child_process(conn):
    conn.send("来自子进程")
    msg = conn.recv()
    print(f"子进程收到: {msg}")

p = Process(target=child_process, args=(child_conn,))
p.start()
print(parent_conn.recv())  # "来自子进程"
parent_conn.send("来自父进程")
p.join()

# 3. Manager（共享对象，支持任意类型）
with Manager() as manager:
    shared_list = manager.list([1, 2, 3])
    shared_dict = manager.dict()

    def modify(lst, d):
        lst.append(4)
        d['key'] = 'value'

    p = Process(target=modify, args=(shared_list, shared_dict))
    p.start()
    p.join()
    print(list(shared_list))  # [1, 2, 3, 4]
    print(dict(shared_dict))  # {'key': 'value'}

# 4. 共享内存（Value/Array，更高效）
from multiprocessing import Value, Array

shared_counter = Value('i', 0)    # 'i' = int
shared_array = Array('d', [0.0, 1.0, 2.0])  # 'd' = double

def increment_shared(counter, lock):
    with lock:
        counter.value += 1

lock = multiprocessing.Lock()
processes = [Process(target=increment_shared, args=(shared_counter, lock)) for _ in range(100)]
for p in processes:
    p.start()
for p in processes:
    p.join()
print(shared_counter.value)  # 100
```

## 协程 asyncio

### 基础概念

```python
import asyncio

# async def 定义协程函数，调用后返回协程对象
async def hello():
    print("Hello")
    await asyncio.sleep(1)  # 非阻塞等待
    print("World")
    return "done"

# 运行协程
result = asyncio.run(hello())  # Python 3.7+

# 协程 vs 函数
# 函数：call -> execute -> return
# 协程：call -> coroutine object -> schedule -> execute (suspend/resume) -> return
```

### 核心 API

```python
import asyncio

async def fetch_data(url, delay):
    """模拟异步 I/O"""
    print(f"开始获取 {url}")
    await asyncio.sleep(delay)
    return f"来自 {url} 的数据"

async def main():
    # 1. create_task：创建任务（立即调度）
    task1 = asyncio.create_task(fetch_data("url1", 1))
    task2 = asyncio.create_task(fetch_data("url2", 2))

    # 2. await：等待任务完成
    result1 = await task1
    result2 = await task2

    # 3. gather：并发执行多个协程，收集所有结果
    results = await asyncio.gather(
        fetch_data("url1", 1),
        fetch_data("url2", 2),
        fetch_data("url3", 1.5),
    )
    print(results)  # 所有结果的列表

    # 4. gather 的 return_exceptions 参数
    results = await asyncio.gather(
        fetch_data("url1", 1),
        asyncio.sleep(0, result=ValueError("error")),
        return_exceptions=True  # 异常作为结果返回而非抛出
    )

    # 5. wait：更灵活的并发控制
    tasks = [asyncio.create_task(fetch_data(f"url{i}", i)) for i in range(5)]
    done, pending = await asyncio.wait(
        tasks,
        return_when=asyncio.FIRST_COMPLETED  # 或 ALL_COMPLETED, FIRST_EXCEPTION
    )
    for task in done:
        print(task.result())
    for task in pending:
        task.cancel()

    # 6. as_completed：按完成顺序获取结果
    tasks = [asyncio.create_task(fetch_data(f"url{i}", 3-i)) for i in range(3)]
    for coro in asyncio.as_completed(tasks):
        result = await coro
        print(result)  # 最快完成的先打印

    # 7. wait_for：带超时的等待
    try:
        result = await asyncio.wait_for(fetch_data("slow", 10), timeout=3)
    except asyncio.TimeoutError:
        print("超时了！")

asyncio.run(main())
```

### 事件循环原理

```python
# asyncio 事件循环的工作原理（简化版）：
#
# 1. 维护一个就绪队列和等待队列
# 2. 从就绪队列取出一个协程执行
# 3. 协程执行到 await 时：
#    - 如果等待的操作已完成 -> 继续执行
#    - 如果等待的操作未完成 -> 放入等待队列，切换到下一个协程
# 4. I/O 事件完成时，将对应协程从等待队列移到就绪队列
# 5. 重复步骤 2-4

# 事件循环底层使用操作系统的 I/O 多路复用：
# - Linux: epoll
# - macOS: kqueue
# - Windows: IOCP (proactor)

# 手动管理事件循环（不推荐，用 asyncio.run 代替）
loop = asyncio.new_event_loop()
try:
    result = loop.run_until_complete(main())
finally:
    loop.close()

# 在已有事件循环中运行（如在 Jupyter Notebook 中）
import nest_asyncio
nest_asyncio.apply()
asyncio.run(main())
```

```python
import asyncio
from asyncio import Semaphore, Lock, Event, Queue

# 1. 异步信号量：限制并发数
async def rate_limited_fetch(sem, url):
    async with sem:  # 最多 N 个并发

async def main():

    tasks = [rate_limited_fetch(sem, f"url{i}") for i in range(100)]

# 2. 异步锁
async def safe_counter():
    lock = Lock()
    counter = 0

    async def increment():
        nonlocal counter
        async with lock:
            temp = counter
            await asyncio.sleep(0)  # 模拟异步操作
            counter = temp + 1

    await asyncio.gather(*[increment() for _ in range(100)])
    print(counter)  # 100

# 3. 异步队列（生产者-消费者）
async def async_producer(q):
    for i in range(10):
        await q.put(f"任务{i}")
        await asyncio.sleep(0.1)
    await q.put(None)  # 结束信号

async def async_consumer(q, name):
    while True:
        item = await q.get()
        if item is None:
            await q.put(None)  # 传递结束信号给其他消费者
            break
        print(f"[{name}] 处理: {item}")
        await asyncio.sleep(0.2)
        q.task_done()

async def main():
    q = Queue(maxsize=5)
    await asyncio.gather(
        async_producer(q),
        async_consumer(q, "C1"),
        async_consumer(q, "C2"),
    )

class AsyncDatabasePool:
    async def __aenter__(self):

        await asyncio.sleep(0.1)  # 模拟连接
        return self

    async def __aexit__(self, exc_type, exc_val, exc_tb):
        print("关闭连接池")
        await asyncio.sleep(0.1)

    async def query(self, sql):
        await asyncio.sleep(0.1)
        return f"result of {sql}"

async def main():
    async with AsyncDatabasePool() as pool:
        result = await pool.query("SELECT * FROM users")

# 5. 异步迭代器
class AsyncRange:
    def __init__(self, n):
        self.n = n
        self.i = 0

    def __aiter__(self):
        return self

    async def __anext__(self):
        if self.i >= self.n:
            raise StopAsyncIteration
        await asyncio.sleep(0.1)
        self.i += 1
        return self.i - 1

async def main():
    async for i in AsyncRange(5):
        print(i)

# 6. 异步生成器（Python 3.6+）
async def async_counter(n):
    for i in range(n):
        await asyncio.sleep(0.1)
        yield i

async def main():
    async for value in async_counter(5):
        print(value)

    # 异步推导式
    results = [i async for i in async_counter(5)]
    results = {i: i**2 async for i in async_counter(5)}
```

### 协程调度原理

```python
# 协程调度的底层机制

# 1. 协程的状态
# CORO_CREATED  -> 刚创建，未执行
# CORO_RUNNING  -> 正在执行
# CORO_SUSPENDED -> 在 await 处暂停
# CORO_CLOSED   -> 已完成或关闭

import inspect

async def example():
    await asyncio.sleep(1)

coro = example()
print(inspect.getcoroutinestate(coro))  # CORO_CREATED

# 2. await 的本质
# await expr 相当于 yield from expr.__await__()
# 协程底层仍然是基于生成器的暂停/恢复机制

# 3. Task 的作用
# Task = 协程 + Future
# Task 负责驱动协程执行（不断调用 send(None)）
# 协程 await 时，Task 注册回调并让出控制权
# 等待的操作完成后，回调触发 Task 继续驱动协程

# 4. 自定义 awaitable 对象
class AsyncTimer:
    def __init__(self, seconds):
        self.seconds = seconds

    def __await__(self):
        yield from asyncio.sleep(self.seconds).__await__()
        return f"等待了{self.seconds}秒"

async def main():
    result = await AsyncTimer(2)
    print(result)

# 5. 运行阻塞代码在异步环境中
async def main():
    loop = asyncio.get_event_loop()

    # 在线程池中运行同步阻塞函数
    result = await loop.run_in_executor(None, blocking_io_function, arg1)

    # 使用 ProcessPoolExecutor 运行 CPU 密集型任务
    from concurrent.futures import ProcessPoolExecutor
    with ProcessPoolExecutor() as pool:
        result = await loop.run_in_executor(pool, cpu_bound_function, arg1)
```

### asyncio 实战模式

```python
# 1. 异步 HTTP 客户端（使用 aiohttp）
import aiohttp

async def fetch_all(urls):
    async with aiohttp.ClientSession() as session:
        tasks = []
        for url in urls:
            tasks.append(fetch_one(session, url))
        return await asyncio.gather(*tasks)

async def fetch_one(session, url):
    async with session.get(url) as response:
        return await response.json()

# 2. 带重试和超时的请求
async def fetch_with_retry(session, url, retries=3, timeout=10):
    for attempt in range(retries):
        try:
            async with asyncio.timeout(timeout):  # Python 3.11+
                async with session.get(url) as resp:
                    return await resp.json()
        except (aiohttp.ClientError, asyncio.TimeoutError) as e:
            if attempt == retries - 1:
                raise
            await asyncio.sleep(2 ** attempt)  # 指数退避

# 3. 异步爬虫框架
async def crawl(urls, max_concurrent=10):
    sem = asyncio.Semaphore(max_concurrent)
    results = []

    async def fetch(url):
        async with sem:
            async with aiohttp.ClientSession() as session:
                async with session.get(url) as resp:
                    return await resp.text()

    tasks = [fetch(url) for url in urls]
    return await asyncio.gather(*tasks, return_exceptions=True)

# 4. 取消和超时
async def long_running():
    try:
        await asyncio.sleep(100)
    except asyncio.CancelledError:
        print("任务被取消")
        # 做清理工作
        raise  # 重新抛出，让调用方知道任务已取消

async def main():
    task = asyncio.create_task(long_running())
    await asyncio.sleep(1)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("确认取消")

# 5. TaskGroup（Python 3.11+，结构化并发）
async def main():
    async with asyncio.TaskGroup() as tg:
        task1 = tg.create_task(fetch_data("url1", 1))
        task2 = tg.create_task(fetch_data("url2", 2))
    # 所有任务完成后才退出 with 块
    # 如果任何任务异常，其他任务会被取消
    print(task1.result(), task2.result())
```

## 并发工具对比

| 方式 | 适用场景 | 是否受 GIL 限制 | 开销 | 共享内存 | 通信方式 |
|------|---------|----------------|------|---------|---------|
| 多线程 | I/O 密集型 | 是（I/O时释放）| 中等 | 是 | 共享变量+锁 |
| 多进程 | CPU 密集型 | 否 | 大 | 否 | Queue/Pipe/Manager |
| 协程 asyncio | 高并发 I/O | 是 | 最小 | 是（单线程）| 异步队列 |
| concurrent.futures | 通用 | 取决于Executor | 中等 | 取决于Executor | Future |

### 如何选择

```python
# 决策树：
# 1. I/O 密集型（网络请求、文件、数据库）
#    -> 首选 asyncio（最高并发）
#    -> 次选 ThreadPoolExecutor（简单、兼容同步库）
#
# 2. CPU 密集型（计算、图像处理、数据分析）
#    -> 使用 ProcessPoolExecutor 或 multiprocessing
#    -> 或使用 numpy/cython 等释放 GIL 的库
#
# 3. 混合型
#    -> asyncio + run_in_executor（线程池处理阻塞I/O，进程池处理CPU）
```

## concurrent.futures

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor
from concurrent.futures import as_completed, wait, FIRST_COMPLETED
import time

# 统一接口：ThreadPoolExecutor 和 ProcessPoolExecutor 用法完全一致
def task(n):
    time.sleep(n)
    return n * n

# 线程池
with ThreadPoolExecutor(max_workers=5) as executor:
    # submit + as_completed：按完成顺序获取结果
    futures = {executor.submit(task, n): n for n in [3, 1, 2]}
    for future in as_completed(futures):
        n = futures[future]
        try:
            result = future.result(timeout=10)
            print(f"task({n}) = {result}")
        except Exception as e:
            print(f"task({n}) 失败: {e}")

    # map：按提交顺序获取结果
    results = list(executor.map(task, [1, 2, 3]))

    # wait：等待条件
    futures = [executor.submit(task, n) for n in [3, 1, 2]]
    done, not_done = wait(futures, return_when=FIRST_COMPLETED)
    print(f"第一个完成: {done.pop().result()}")

# 进程池
with ProcessPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(cpu_bound_task, data_chunks))

# Future 对象的方法
future = executor.submit(task, 5)
future.done()        # 是否完成
future.cancelled()   # 是否被取消
future.cancel()      # 尝试取消
future.result()      # 获取结果（阻塞）
future.exception()   # 获取异常
future.add_done_callback(callback)  # 添加完成回调
```

## 踩坑指南

### 坑1：多线程共享可变状态
```python
# 即使是简单的 counter += 1 也不是线程安全的
# 因为 += 在字节码层面是 LOAD + ADD + STORE 三步操作
counter = 0

def unsafe_increment():
    global counter
    for _ in range(100000):
        counter += 1  # 不安全！

# 解决：使用 Lock 或 threading 安全的数据结构
```

### 坑2：asyncio 中使用阻塞调用
```python
# 错误！阻塞调用会卡住整个事件循环
async def bad():
    import requests
    data = requests.get("http://example.com")  # 阻塞！
    time.sleep(1)  # 阻塞！

# 正确做法
async def good():
    # 使用异步库
    async with aiohttp.ClientSession() as session:
        async with session.get("http://example.com") as resp:
            data = await resp.json()

    # 或用 run_in_executor 包装阻塞调用
    loop = asyncio.get_event_loop()
    data = await loop.run_in_executor(None, requests.get, "http://example.com")
    await asyncio.sleep(1)  # 非阻塞 sleep
```

### 坑3：进程池传递不可 pickle 的对象
```python
# multiprocessing 使用 pickle 序列化/反序列化数据
# lambda、局部函数、未实现 __reduce__ 的对象不可 pickle

# 错误
# pool.map(lambda x: x**2, range(10))  # PicklingError

# 正确：使用模块级函数
def square(x):
    return x ** 2

pool.map(square, range(10))
```

### 坑4：asyncio 的异常被吞掉
```python
# 如果不 await 一个 Task，它的异常会被静默吞掉

async def main():
    task = asyncio.create_task(risky_coroutine())
    # 如果不 await task，异常不会被发现
    # 直到 task 被垃圾回收时才会打印警告

    # 正确做法：总是 await 或用 TaskGroup
    try:
        await task
    except Exception:
        pass
```

### 坑5：混用 asyncio.run 和手动事件循环
```python
# asyncio.run() 会创建新的事件循环
# 不能在已有事件循环中调用 asyncio.run()
# 在 Jupyter Notebook 中需要特殊处理

# 在同步代码中运行协程
import asyncio

# 方式1: asyncio.run (推荐)

```

## 最佳实践

1. **I/O 密集首选 asyncio**：比多线程更轻量、更高并发
2. **CPU 密集用多进程**：绕过 GIL，充分利用多核
3. **使用 concurrent.futures 统一接口**：方便在线程池和进程池间切换
4. **最小化锁的范围**：只锁必要的代码段
5. **避免共享状态**：使用消息传递（Queue）替代共享变量
6. **使用 asyncio.TaskGroup（Python 3.11+）**：结构化并发，自动取消
7. **阻塞调用用 run_in_executor**：不要阻塞事件循环
8. **合理设置并发数**：线程池通常 `min(32, os.cpu_count() + 4)`，进程池为 CPU 核数
9. **使用 Semaphore 限流**：避免同时发起过多请求
10. **graceful shutdown**：处理取消和超时，做好资源清理

## 面试高频问题

### Q1: GIL 是什么？为什么存在？怎么绕过？
**答**：GIL 是 CPython 的全局解释器锁，同一时刻只允许一个线程执行字节码。存在原因：保护引用计数的线程安全，简化 C 扩展的编写。绕过方法：(1) 多进程 multiprocessing；(2) C 扩展释放 GIL（如 numpy）；(3) Cython 的 `with nogil`；(4) Python 3.13+ 实验性的 free-threaded mode。I/O 操作时 GIL 会自动释放，所以 I/O 密集型任务多线程仍然有效。

### Q2: 多线程、多进程、协程分别适合什么场景？
**答**：多线程适合 I/O 密集型（网络请求、文件读写），因为 I/O 时释放 GIL；多进程适合 CPU 密集型（数据计算、图像处理），每个进程独立 GIL；协程 asyncio 适合高并发 I/O（Web服务器、爬虫），单线程内通过事件循环调度，开销最小。混合场景用 asyncio + run_in_executor。

### Q3: asyncio 的事件循环是怎么工作的？
**答**：事件循环维护就绪队列和等待队列。从就绪队列取协程执行，遇到 await 时若操作未完成则放入等待队列并切换到下一个协程。底层使用 OS 的 I/O 多路复用（Linux 用 epoll，macOS 用 kqueue）监听 I/O 事件，事件完成时将协程移回就绪队列。这实现了单线程内的并发。

### Q4: 如何避免死锁？
**答**：(1) 锁排序——所有线程按相同顺序获取锁；(2) 超时机制——`lock.acquire(timeout=N)`；(3) 避免嵌套锁——简化锁的使用；(4) 使用 RLock 替代 Lock（允许同一线程重入）；(5) 使用更高级的同步原语（Queue、Event）替代显式锁；(6) 尽量使用无锁设计（消息传递、不可变数据）。

### Q5: Python 中如何实现线程安全？
**答**：(1) 使用 Lock/RLock 保护共享状态；(2) 使用 threading.local() 线程本地存储；(3) 使用 queue.Queue 线程安全队列；(4) 使用 atomic 操作（如 `list.append` 是线程安全的，因为 GIL 保证单个字节码操作的原子性）；(5) 使用不可变对象避免修改；(6) 使用 concurrent.futures 返回独立的 Future 对象。

### Q6: asyncio.gather 和 asyncio.wait 的区别？
**答**：`gather` 接收协程列表，返回结果列表（按输入顺序），支持 `return_exceptions` 参数。`wait` 接收 Task 集合，返回 `(done, pending)` 两个集合，支持 `return_when` 参数（`FIRST_COMPLETED`、`FIRST_EXCEPTION`、`ALL_COMPLETED`）。`gather` 更简单适合收集所有结果，`wait` 更灵活适合需要部分完成就处理的场景。

### Q7: 进程间通信有哪些方式？各有什么特点？
**答**：(1) Queue——最常用，支持多生产者多消费者，线程/进程安全；(2) Pipe——仅两个进程间通信，速度最快；(3) Manager——支持共享任意 Python 对象（list/dict 等），最灵活但最慢（通过代理对象网络通信）；(4) Value/Array——共享内存，速度快但只支持简单类型；(5) mmap——内存映射文件；(6) 消息队列（Redis/RabbitMQ 等外部工具）。

### Q8: 如何在 asyncio 中运行同步阻塞代码？
**答**：使用 `loop.run_in_executor(executor, func, *args)`。传入 None 使用默认线程池（适合阻塞 I/O），传入 ProcessPoolExecutor 适合 CPU 密集型。示例：`await loop.run_in_executor(None, requests.get, url)`。Python 3.9+ 可用 `asyncio.to_thread(func, *args)` 简化。

### Q9: Python 3.11+ 的 TaskGroup 有什么优势？
**答**：TaskGroup 实现了结构化并发：(1) 所有任务在 `async with` 块内管理，确保生命周期清晰；(2) 如果任何任务抛出异常，其他任务会自动取消；(3) 异常会以 ExceptionGroup 形式传播，不会丢失；(4) 比 gather 更安全，避免了"fire and forget"导致的异常被吞掉。

### Q10: 什么是 cooperative multitasking？asyncio 中如何保证公平调度？
**答**：协作式多任务是指协程主动让出控制权（通过 await），而非被抢占。每个协程负责在合适的时机 await，让事件循环调度其他协程。如果协程长时间不 await（如执行大量 CPU 计算），会阻塞整个事件循环。保证公平的方法：(1) 在计算密集循环中定期 `await asyncio.sleep(0)`；(2) 将 CPU 密集任务放到线程池/进程池（`run_in_executor`）；(3) 避免任何同步阻塞调用。
