# Part 2 · 04 — 记忆与个性化

> 这是 SparkOffer 最有辨识度的一章。讲清四件事：**Mem0 风格的两阶段画像更新**（怎么避免记忆无限膨胀）、**自研向量记忆**（为什么 SQLite+numpy 就够）、**确定性掌握度算法 + SM-2 间隔重复**（怎么量化进步且不靠 LLM 主观分）、以及**知识自进化**。

---

## 0. 先看全景：什么在"记忆"，存在哪

个性化的真相源是每个用户的 `profile.json`（`data/users/<uid>/profile/profile.json`），结构（`memory.py:39-85` 的 `DEFAULT_PROFILE`）：

```
profile.json
├─ topic_mastery        各领域掌握度 {score: 0-100, notes}
├─ weak_points[]        薄弱点 {point, topic, times_seen, improved, mastery, sr:{...}}
├─ strong_points[]      强项
├─ communication        沟通风格 {style, habits[], suggestions[]}
├─ thinking_patterns    思维模式 {strengths[], gaps[]}
├─ preferences          用户偏好 {response_style, preferred_difficulty, ...}
└─ stats                统计 {total_sessions, avg_score, score_history[]}
```

加上一层**向量记忆**（`memory_vectors` 表，BLOB 存 embedding）做"语义召回历史洞察"。

> **核心设计哲学（三句话）**：
> 1. **文件即真相**（OpenClaw 风格）：`profile.json` 可人工编辑、可读、可导出。
> 2. **两阶段提取**（Mem0 风格）：Extract → Update，不无脑追加。
> 3. **向量库当 embedding 缓存**，不当真相源——profile.json 才是。

## 1. Mem0 风格两阶段画像更新（最核心的创新）

### 1.1 问题：为什么不能无脑 append

最朴素的画像更新：每次面试发现薄弱点就 `weak_points.append(...)`。**灾难在哪**？
- 同一个概念用户会反复出错（"GIL 理解不深"可能出现 10 次），描述还每次略有不同。
- 几十次训练后，画像变成几百条**语义重复**的条目——又臭又长，塞进 prompt 还浪费 token、稀释信号。

### 1.2 Mem0 的思路

**Mem0** 是一个流行的 LLM 记忆框架，核心思想：**新记忆进来时，让 LLM 决定它和已有记忆的关系**——是新增、是更新某条、还是无需操作。本项目借鉴这个思路，做成**两阶段**。

### 1.3 本项目实现（`memory.py`）

**总入口**：`update_profile_after_interview`（`memory.py:722-787`），两阶段：

#### 阶段 1 — Extract（提取）

把本次对话 transcript + 评分喂给 LLM（`EXTRACT_PROMPT`），让它提取**本次新发现**的结构化洞察：weak_points / strong_points / topic_mastery notes / 沟通观察 / 思维模式 / 维度分。规则明确写在 prompt 里：「只提取本次明确暴露的，不要猜测；薄弱点要具体」。

#### 阶段 2 — Update（智能合并）

`llm_update_profile`（`memory.py:622`）把**已有画像（带索引）+ 本次新发现**再喂给 LLM（`PROFILE_UPDATE_PROMPT`），让它对每条新发现决定一个**操作**：

```python
# LLM 返回的 ops 被 _apply_memory_ops 执行 (memory.py:435-474)
weak_point_ops: [
  {"action": "ADD",    "point": "新薄弱点", "topic": "python"},      # 全新 → 新增
  {"action": "UPDATE", "index": 3, "new_point": "更精确的描述"},     # 已有 → 更新+计数+1
  {"action": "NOOP"},                                                # 重复 → 不动
]
improvements: [{"weak_index": 2}]   # 标记某薄弱点 improved=True（IMPROVE）
strong_point_ops: [...]
```

四种操作语义：

| 操作 | 含义 | 效果 |
|---|---|---|
| **ADD** | 全新的点 | 追加，初始 `mastery=20`（"未证明"）、`times_seen=1` |
| **UPDATE** | 已有点的更精确表述 | 改写 `point`、`times_seen+1`、刷新 `last_seen` |
| **NOOP** | 语义重复 | 什么都不做 |
| **IMPROVE** | 之前的薄弱点已克服 | 标 `improved=True`，移出活跃薄弱点 |

#### 降级兜底：LLM 解析失败怎么办

LLM 返回的 JSON 可能格式坏。`_parse_json_safe`（`memory.py:412-432`）先尽力解析（裸 JSON / ```json 围栏 / 前缀有废话三种都试）；**真解析不出来**，就调 `_deterministic_update`（`memory.py:477-517`）——用**向量余弦去重**做确定性合并（阈值 0.75，见 §3）。

> **面试金句**：「Mem0 的思路是让 LLM 做语义合并，我在它之上又加了一层保险——LLM 解析失败时 fallback 到向量 cosine 去重。**智能优先、确定性兜底**，画像几十次训练后仍然精炼。」

### 1.4 画像里"确定性"和"LLM"的分工

这是个关键区分，务必讲清：

| 字段 | 更新方式 | 为什么 |
|---|---|---|
| weak_points / strong_points 的**合并** | **LLM 决策**（ADD/UPDATE/NOOP/IMPROVE） | 语义合并需要理解力 |
| topic_mastery **分数** | **确定性 EWMA**（`§4`） | 分数不能靠 LLM 主观判断 |
| communication / thinking_patterns | 确定性追加去重 | 简单 set 语义 |
| stats（场景均分、score_history） | 确定性算 | 纯统计 |

> **被质疑"LLM 打分不靠谱"时的标准回答**：「我的掌握度是**确定性公式**，不依赖 LLM 主观分。LLM **只**负责薄弱点的语义合并——那是它擅长的；打分这种要可复现的事，交给算法。」

## 2. 自研向量记忆：SQLite BLOB + numpy

### 2.1 为什么不用 Milvus/Pinecone

长期记忆的规模是**百级/单用户**（上限 500 条，`MAX_VECTORS_PER_USER`）。这个规模下：
- Milvus/Pinecone 的分布式索引（HNSW/IVF）是**杀鸡用牛刀**，还引入运维负担。
- 直接把 embedding 存 SQLite BLOB、用 numpy 全量算余弦，**毫秒级**就够。

> **这是刻意的"按规模选型"**，是工程成熟度的体现。面试时绝不能说成"用了主流向量库"——那反而是失分。

### 2.2 怎么存怎么算（`vector_memory.py` + `vector_store/`）

- **存**：`memory_vectors` 表，`embedding` 字段是序列化的 numpy 向量（BLOB）。可插拔后端 `numpy_store`（默认）/ `qdrant_store`（可选）。
- **算**：`search_memory`（`vector_memory.py:314-350`）把该用户全部向量拉出来（≤500 行），算余弦 → 时间衰减 → 排序 → top_k。这些 CPU 密集操作用 `asyncio.to_thread` 移出事件循环。

### 2.3 时间衰减（Time Decay）

新洞察应该比老洞察更重要。指数衰减（`_time_decay`, `vector_memory.py:240-251`）：

```python
decay = 0.5 ** (age_days / 14.0)               # 14 天半衰期
final_score = raw_cosine * (0.3 * decay + 0.7) # 最多削 30% 权重
```

- **14 天半衰期**：14 天前的洞察衰减到一半。
- **最多削 30%**（`TIME_DECAY_WEIGHT=0.3`）：即便很老的洞察也保留 70% 权重——不彻底埋没历史。
- **为什么衰减放在检索后、截断前**：必须先对全集衰减再排序取 top_k，否则"老但相关"的会被错误截掉。两个后端都在应用层统一做这步，保证 numpy 和 qdrant 排序一致。

### 2.4 薄弱点语义去重（向量匹配的精华实现）

`find_similar_weak_point`（`vector_memory.py:353-421`）——判断"新薄弱点"是否和已有的某条语义重复（阈值 0.75）。实现有三个工程亮点：

1. **矩阵化余弦 + argmax**：不是 N 次 `reshape(1,-1)` 循环（每次重算 new_vec 的范数），而是把所有已有点堆成矩阵，**一次** `_cosine_similarity` + `argmax`。
2. **缓存命中 + 批量补嵌**：已有点的 embedding 从向量库缓存取，未命中的**一次批量** embed，再写回缓存（被 LLM UPDATE 改写过的点不会每次重嵌）。
3. **维度不一致自愈**：换过 embedding 模型后，旧缓存维度和新 query 不符——此时当 miss 重嵌（避免 `np.stack` 崩溃），极端情况维度仍不符就**放弃去重返回 None**（绝不让维度不匹配把请求打挂）。

> 这一段是"把一个简单功能写到生产级"的范例——可以专门拿出来讲，体现你对**性能、缓存、容错**的全面考量。

### 2.5 容量管理

写入时过滤掉全零兜底向量（embedding 失败时返回的零向量不能入库，否则污染检索）；写完调 `cleanup_oldest` 把超过 500 条的最旧记录清掉。

## 3. 掌握度算法：确定性 + EWMA

### 3.1 confidence 贡献公式

每答一题，对相关薄弱点产生一个 0-100 的"贡献分"（`spaced_repetition.py:100-103`）：

```python
contribution = (难度/5) × (得分/10) × 100
# 难度夹 [1,5]，得分夹 [0,10]
```

直觉：**高难度题答对，比低难度题答对更能证明掌握**。一道 5 星题拿 10 分 → 贡献 100；一道 1 星题拿 10 分 → 贡献只有 20。

### 3.2 EWMA（指数加权移动平均）平滑

掌握度不是直接取贡献，而是和旧值做 EWMA：

```python
# per-WP 掌握度 (spaced_repetition.py:134) —— 偏向旧值, 平滑防误毕业
wp["mastery"] = round(0.7 * prev_mastery + 0.3 * contribution)

# topic 级掌握度 (memory.py:541) —— 偏向新值, 整体跟随近况
merged = old_score * (1 - 0.7) + new_score * 0.7
```

**为什么两个粒度方向相反**（这是个会被追问的点）：
- **单点（per-WP）偏旧（0.7 旧）**：单个薄弱点平滑，防止一次发挥失常或侥幸答对就"误判毕业"。
- **整体（topic）偏新（0.7 新）**：领域整体掌握度该快速跟随近期表现。

> **EWMA 是什么**：一种只需保存"上一个值"就能增量更新的滑动平均，新数据权重大、老数据指数衰减。比"全历史平均"更跟手，比"只看最新"更稳。

## 4. SM-2 间隔重复（Spaced Repetition）

### 4.1 是什么

**间隔重复**是记忆科学的成熟方法：**答对了下次复习间隔拉长，答错了重置到明天**——把复习精力集中在快忘的内容上。**SM-2** 是 Anki 等软件用的经典算法。

### 4.2 本项目实现（`spaced_repetition.py:13-53`）

```python
quality = min(5, int(score_0_10 / 2))   # 0-10 分映射到 SM-2 的 0-5 质量
if quality >= 3:                         # 通过
    if reps == 0:   interval = 1         # 第一次：1 天后
    elif reps == 1: interval = 3         # 第二次：3 天后（比标准 SM-2 的 6 天更激进——面试备考要更快二刷）
    else:           interval = round(interval * ease_factor)  # 之后：上次间隔 × 难度因子
    reps += 1
else:                                    # 没通过
    interval = 1; reps = 0               # 重置到明天
ease_factor = max(1.3, ef + (0.1 - (5-quality)*(0.08 + (5-quality)*0.02)))  # 永不低于 1.3
```

工程细节：
- **`round` 不用 `int`**：截断会系统性把间隔压低，导致过度安排复习。
- **`ease_factor` 下限 1.3**：标准 SM-2 约束，防止间隔退化到永远很短。

### 4.3 自定义"毕业"机制（关键改进）

薄弱点什么时候算"克服了"（`improved=True`）？

> **不能用 SM-2 原生的 `repetitions`**——它在 `quality>=3`（即 score≥6）时就 +1，意味着连续考 6 分（及格边缘）也会"毕业"，太松。

本项目单独维护 `consecutive_high` 计数（`spaced_repetition.py:127-145`）：**连续 3 次 ≥7 分**才毕业，期间任何一次 <7 就清零：

```python
new_sr["consecutive_high"] = (prev.get("consecutive_high", 0) + 1) if score >= 7 else 0
if new_sr["consecutive_high"] >= 3:
    wp["improved"] = True               # 毕业，移出活跃薄弱点
    profile["strong_points"].append({"point": f"已掌握: {wp['point']}", ...})
```

### 4.4 复习调度怎么影响出题

`get_due_reviews`（`spaced_repetition.py:56-77`）取出"今天到期复习"的薄弱点，按 `ease_factor` **最难的排前面**。出题管道（`drill_pipeline._stage_prepare`）把到期薄弱点插到 query 列表最前——**优先考今天该复习的**。

### 4.5 一个细节：更新所有匹配的薄弱点

评估器报的薄弱点提示（如 "GIL"）可能同时匹配用户的多条薄弱点（"对 GIL 理解不深" + "Python 并发模型薄弱"）。`update_weak_point_sr` **更新所有子串匹配的 WP**，不只第一条——否则第二条的掌握度会和真实表现悄悄失同步。

## 5. 文件即真相：原子写 + 文件锁

`profile.json` 是真相源，并发读改写会出问题。本项目两道防护（`memory.py`）：

### 5.1 Per-user 文件锁

```python
_profile_locks: dict[str, threading.Lock]   # 每个 user 一把锁
```

`_load_profile` / `_save_profile` 都在该用户的锁内操作，**防止并发 read-modify-write 竞争**（比如答题更新和画像更新同时跑）。

### 5.2 原子写（write-temp-then-rename）

```python
fd, tmp_path = tempfile.mkstemp(dir=同目录)   # 写到同目录临时文件
os.fdopen(fd).write(data)
os.replace(tmp_path, path)                     # 原子重命名
```

`os.replace` 在同文件系统内是**原子操作**——进程写到一半崩溃，要么是完整旧文件、要么是完整新文件，**绝不会出现半截损坏的 JSON**。

### 5.3 一个微妙 bug 的防御：deepcopy 默认值

新用户读不到 profile.json 时返回 `copy.deepcopy(DEFAULT_PROFILE)`——**不是 `.copy()`**。因为浅拷贝会共享 `DEFAULT_PROFILE` 里的嵌套 list/dict，给新用户的 weak_points 加一条，会泄漏进全局默认值、污染下一个新用户的"空"画像。这种细节体现对**可变默认值陷阱**的警觉。

## 6. 知识自进化（Knowledge Evolution）

训练不只更新画像，还反哺知识库（`knowledge_evolution.py`）：

| 触发 | 动作 | 落点 |
|---|---|---|
| 答案得分 **≥7** | LLM 提炼知识点 | 追加到知识库 `自动沉淀.md`（带 `<!-- 自动沉淀 时间 -->` 标记），增量入向量索引 |
| 答案得分 **<6** | 收集为高频错题 | `data/users/<uid>/high_freq/<topic>.md`，供后续重点复练 |

- **增量索引**：只 embedding 新沉淀的内容（`schedule_incremental_insert`，走后台任务队列），不重建整库。
- **进化统计**：`profile` 路由用正则统计 `自动沉淀` 标记数、最近进化时间，前端可视化"知识库在自我成长"。

> 这条线让系统形成**正反馈**：你答得好的内容沉淀成知识、答得差的进高频库——**知识系统越用越丰富**。

## 7. 三层上下文融合：个性化出题的最终形态

出题前融合三层（README 的核心图，落在 `drill_pipeline._stage_prepare/generate`）：

```
Layer 3 · 长期画像   跨领域思维模式 / 沟通风格（get_profile_summary_for_drill）
Layer 2 · 领域掌握度  0-100 掌握度 / 历史薄弱点 / 过往洞察（get_topic_context_for_drill）
Layer 1 · 会话上下文  知识库 RAG / 最近 20 题去重 / SM-2 到期复习
        ↓ 全部塞进 token 预算装配器（06 章）
   LLM 生成 10 道高度个性化的题（梯度难度 + 前 3 题命中薄弱点）
```

梯度策略：掌握度 0-30 主打概念辨析、30-60 场景应用、60-100 系统设计与权衡（`_strategy_for_mastery`）。更精细的版本用 **slot 槽位分配**（`prompts/strategies.allocate_slots`）按每个薄弱点的掌握度"排兵布阵"考什么。

## 本章小结

- **Mem0 两阶段**（Extract→Update，ADD/UPDATE/NOOP/IMPROVE + 向量去重兜底）让画像精炼不膨胀。
- **自研向量记忆**（SQLite BLOB + numpy + 14 天时间衰减 + 矩阵化余弦）是"按规模选型"的范例。
- 掌握度走**确定性 EWMA 公式**、复习走 **SM-2 + 自定义毕业（连续 3 次 ≥7）**——量化进步不靠 LLM 主观分。
- **文件即真相 + 文件锁 + 原子写** 是生产级的数据安全考量。
- **知识自进化**形成"越练越懂你、知识库越用越丰富"的正反馈。
