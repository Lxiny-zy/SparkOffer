# Part 2 · 09 — 前端工程

> 前端是 React 19 + Vite + TypeScript 的现代单页应用。本章讲清 **React 核心范式（组件/Hooks/Suspense/lazy）、路由与鉴权、SSE 流式客户端（与后端流式对接的另一半）、以及数据可视化**。后端岗位也该能讲清前端这套——尤其 SSE 客户端，是"30 秒→3 秒"体验的前端半边。

---

## 1. React 19 基础范式

### 1.1 函数组件 + Hooks

现代 React 全用**函数组件**，状态和副作用靠 **Hooks**：

| Hook | 作用 | 项目里的典型用法 |
|---|---|---|
| `useState` | 组件局部状态 | 题目列表、加载态、输入框 |
| `useEffect` | 副作用（订阅/请求/清理） | 进页面拉数据、卸载时 abort SSE |
| `useCallback` | 缓存函数引用 | 传给子组件的回调，避免无谓重渲染 |
| `useContext` | 跨组件共享状态 | `AuthContext`（token/登录态） |
| 自定义 Hook | 复用逻辑 | `useDraftPersist`（草稿持久化）、`useTilt`（卡片倾斜特效） |

### 1.2 Context 做全局状态

`AuthContext`（`contexts/AuthContext.tsx`）用 `useContext` 在全应用共享 `{token, loading, ...}`。`App.tsx` 里 `ProtectedRoute`/`PublicHome`/`AuthPage` 都靠它判断登录态决定渲染什么——比 Redux 轻，够这个规模用。

### 1.3 错误边界（ErrorBoundary）

`components/ErrorBoundary.tsx` 包住路由——某个页面渲染崩了只显示降级 UI，不白屏整个应用。这是 React 处理渲染期异常的标准机制。

## 2. 代码分割：Suspense + lazy（首屏性能）

### 2.1 是什么 / 为什么

单页应用如果把所有页面打成一个大 bundle，首屏要下载全部代码——慢。**代码分割（code splitting）**：每个路由打成独立 chunk，**访问到才加载**。

### 2.2 本项目实现（`App.tsx`）

```tsx
const Interview = lazy(() => import("./pages/Interview"));   // 16 个页面懒加载
const Review = lazy(() => import("./pages/Review"));
// ...
<Suspense fallback={<Loader2 className="animate-spin" />}>   // chunk 加载时显示 spinner
  <Routes>...</Routes>
</Suspense>
```

- `lazy(() => import(...))`：把页面组件变成"用到才动态 import"。
- `Suspense`：在 lazy 组件的 chunk 还在下载时，渲染 `fallback`（loading 动画）。
- 只有首屏必需的 `Landing/Login/Home` 是直接 import（不 lazy）——首屏立刻可用。

> 效果：首屏只下载 Home + 框架代码，进 Interview 页才下载 Interview 的 chunk。19 个页面里 16 个按需加载。

## 3. 路由：React Router v7

```tsx
<BrowserRouter>
  <Routes>
    <Route path="/" element={<PublicHome />} />               // 未登录→Landing, 登录→Home
    <Route path="/interview/:sessionId" element={
      <ProtectedRoute><Interview /></ProtectedRoute>          // 受保护路由
    } />
    <Route path="*" element={<NotFound />} />
  </Routes>
</BrowserRouter>
```

- **声明式路由**：URL ↔ 组件映射。
- **动态参数**：`:sessionId` 等。
- **受保护路由**：`ProtectedRoute` 包一层，未登录 `<Navigate to="/" />` 重定向。
- **会话过期处理**：`onSessionExpired` 回调——token 失效时全局跳登录。

19 个页面：Landing/Login/Home/Interview/Review/History/Profile/TopicDetail/Knowledge/KnowledgeTraining/Graph/JobPrep/Favorites/AlgorithmSolver/AlgorithmCollection/Settings/QAArena/RAGDashboard/NotFound。

## 4. SSE 流式客户端（与后端流式对接的另一半）

后端推 SSE（06 章），前端得有对应的**消费**逻辑。`api/sse.ts` + `api/client.ts` 这套是体验的关键。

### 4.1 超时包装（AbortController）

```tsx
const SSE_TIMEOUT_MS = 360000;   // 6 分钟硬上限
export async function withSSETimeout<T>(fn, timeoutMs = SSE_TIMEOUT_MS) {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), timeoutMs);
  try { return await fn(controller.signal); }
  catch (e) { throw _timeoutError(e, timeoutMs); }   // AbortError → "请求超时"
  finally { clearTimeout(timeoutId); }
}
```

- **AbortController** 是浏览器原生的"取消 fetch"机制——超时就 `abort()`，fetch 抛 `AbortError`，映射成本地化的"请求超时"提示。
- **6 分钟超时**：注释写明——出题最坏情况 retrieve(90s)+generate(70s)+validate/repair(60s)+余量。早先用 120s 在复杂出题+网络抖动时会误杀正常请求，让用户看到 "network error"。后端 30s 心跳兜底真正的卡死，所以前端给足 6 分钟。**前后端超时是协同设计的。**

### 4.2 生成器形态 + 外部信号

`withSSETimeoutGen` 是生成器版（`yield*` 透传帧），还支持**外部 signal**——组件卸载时 abort，立即释放连接（而不是等下一个 chunk 才发现该停了）：

```tsx
if (externalSignal) externalSignal.addEventListener("abort", () => controller.abort());
```

这呼应 `useEffect` 的清理：进页面开流、离开页面（cleanup）abort，**不泄漏连接**。

### 4.3 流式 vs 普通 JSON 自适应

`fetchSSE` 一个函数兼容两种响应（`sse.ts:78-131`）：

```tsx
const contentType = res.headers.get("content-type") || "";
if (!contentType.includes("text/event-stream")) return res.json();  // 非流式直接 json（缓存命中等）
for await (const event of iterSSEFrames(res)) {                      // 流式逐帧消费
  switch (event.type) {
    case "progress": callbacks?.onProgress?.(event.message); break;
    case "content":  callbacks?.onContent?.(event.delta);   break;  // 真流式逐 token 渲染
    case "error":    throw new Error(event.message);
    case "complete": result = event.data; break;
  }
}
```

- `iterSSEFrames`（`client.ts`）把响应流按 `\n\n` 切帧、`JSON.parse` 成事件对象，用 **async generator** `for await` 消费。
- 回调式：`onProgress`（进度）/`onContent`（逐 token）让页面边收边渲染——这是"生成一道渲染一道"的前端落点。

> **面试金句**：「前端 SSE 客户端和后端是协同设计的——后端 30s 心跳防真卡死，前端给 6 分钟硬超时防误杀；用 AbortController 实现超时和组件卸载时的连接释放；`fetchSSE` 一个入口自适应流式/普通 JSON，逐帧回调驱动'生成一道渲染一道'。」

## 5. 数据可视化

### 5.1 Recharts（成长曲线）

`components/charts/` 6 个图表（基于 **Recharts** 3.8）：

| 图表 | 展示 |
|---|---|
| `ScoreTrendChart` | 历史得分趋势（折线） |
| `DimensionTrendChart` | 技术深度/沟通/思维等维度趋势 |
| `TopicRadarChart` | 各领域掌握度（雷达图） |
| `LearningHeatmap` | 训练频率热力图（按日期） |
| `KnowledgeTreemap` | 知识覆盖矩形树图 |
| `SessionFrequencyChart` | 会话数柱状图 |

这些把"可累积的能力建模"可视化出来——呼应产品定位（练得越多越懂你，且**看得见成长**）。

### 5.2 力导向图（题目关联）

`react-force-graph-2d`（`pages/Graph.tsx`）画**题目关联图**——题目按语义相似度连边（后端 `graph.py` 算相似，阈值 0.65），力导向布局自动聚类相关题目。

### 5.3 Markdown + 代码高亮

AI 输出是 Markdown，用 `react-markdown` + `remark-gfm`（GitHub 风格：表格/任务列表）渲染，代码块用 `react-syntax-highlighter` 高亮。

## 6. 样式与 UI 组件

- **Tailwind CSS v4**：原子化 CSS，类名即样式。配 `@tailwindcss/vite` 插件。
- **Radix UI**（shadcn 风格）：`components/ui/` 下的 button/card/dialog/tooltip/tabs 等基于 Radix——**无障碍（a11y）+ 无样式原语**，自己套 Tailwind 皮肤。这是当前 React UI 的主流方案。
- **lucide-react**：图标库。**sonner**：toast 通知。`class-variance-authority` + `clsx` + `tailwind-merge`：管理条件类名。

---

## 7. 构建：Vite + TypeScript

- **Vite 8**：开发期 ESM 原生 + HMR（热更新极快），生产期 Rollup 打包。比 webpack 快一个量级。
- **TypeScript 6**：全前端类型安全。`types/api.ts` 定义 API 响应类型，和后端 Pydantic 模型对齐，前后端类型一致。

## 本章小结

- React 19 **函数组件 + Hooks + Context**；**ErrorBoundary** 防整页崩。
- **Suspense + lazy** 路由级代码分割，16 个页面按需加载，首屏只下必需代码。

- 可视化：Recharts 成长曲线 + 力导向题目关联图 + Markdown/代码高亮。
- Tailwind v4 + Radix（shadcn）+ Vite + TS，现代前端标准栈。
