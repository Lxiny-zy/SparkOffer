## 1. Docker Compose 编排（`docker-compose.yml`）

### 1.1 四个服务

```
┌─ frontend (nginx)  9000:80  ──反代──┐
│                                     ↓
├─ backend  (uvicorn) 9001:8000 ──────┤
│     ├── redis    (缓存, 软依赖)      │
│     └── qdrant   (向量, 软依赖)      │
```

| 服务 | 镜像/构建 | 端口 | 角色 |
|---|---|---|---|
| `frontend` | nginx（构建 React 产物） | 9000:80 | 静态资源 + 反代 `/api` 到后端 |
| `backend` | uvicorn（FastAPI） | 9001:8000 | 业务逻辑 |
| `redis` | redis:7-alpine | — | 缓存（256mb，LRU 淘汰） |
| `qdrant` | qdrant/qdrant | 6333/6334 | 可选向量后端 |

### 1.2 编排里的工程考量

- **健康检查 + 启动依赖**：`backend` 等 `redis` healthy 才起；`frontend` 等 `backend` healthy 才起（`depends_on` + `condition`）。后端健康检查是访问 `/docs`。
- **qdrant 是软依赖**：`condition: service_started`（不等 healthy）——因为 qdrant 基于 distroless 无 shell 没法 exec 健康检查，且**后端连不上 qdrant 会自动降级 numpy**，所以不阻塞启动。这是"可选依赖不该拖垮主流程"的体现。
- **数据卷持久化**：`./data` 挂进后端（SQLite、用户目录、向量），`./data/redis`、`./data/qdrant` 各自持久化。
- **资源限制**：backend 限 2G 内存；redis `maxmemory 256mb` + `allkeys-lru`（满了淘汰最久未用）。
- **`restart: unless-stopped`**：崩了自动拉起。

## 2. nginx 反向代理 + 流式调优（`frontend/nginx.conf`）

nginx 既服务前端静态资源，又反代 `/api` 到后端。**关键是对 SSE 流式的调优**：

```nginx
location /api/ {
    proxy_pass http://backend:8000;
    proxy_read_timeout 300s;       # 长推理/出题留够时间（后端 read 设 360s 比它高一层）
    proxy_send_timeout 300s;
    proxy_buffering off;           # 关键！关缓冲，SSE 才能逐帧实时下发
    proxy_cache off;
    proxy_http_version 1.1;        # SSE 需要 HTTP/1.1 长连接
    proxy_set_header Connection '';# 清空 Connection 头，保持长连接（不被 close）
}
```

| 配置 | 为什么 |
|---|---|
| `proxy_buffering off` | **流式的命门**——开着的话 nginx 会攒一批响应再发，前端收不到实时 token。配合后端 `X-Accel-Buffering: no` 双保险 |
| `proxy_read_timeout 300s` | 长出题/推理不被中途掐断；后端 httpx read=360s **故意比它高**，让超时只由 nginx 一层兜（呼应 05 章） |
| `proxy_http_version 1.1` + `Connection ''` | SSE 依赖 HTTP/1.1 持久连接 |

静态资源的缓存策略也分两类：
- `/assets/`（文件名带哈希）→ `expires 1y, immutable`（激进缓存，内容变了文件名就变）；
- `index.html` → `no-cache`（永远拉最新，保证发版立即生效）。

## 3. ASR 录音转写（可选能力，`transcribe.py`）

"录音复盘"功能：上传面试录音 → 转写 → 结构化 Q&A → 逐题分析。转写链路是 **七牛云 OSS + DashScope ASR**：

```
音频 bytes → 写临时文件 → 上传七牛云 OSS（拿公网 URL）
          → DashScope qwen3-asr-flash-filetrans 异步提交（X-DashScope-Async）
          → 轮询 task_id 直到 SUCCEEDED（最多 300 次 ×3s）
          → 拉 transcription_url 提取文本
```

工程细节：
- **为什么要先传 OSS**：DashScope 的 filetrans 接口要一个**公网可访问的 URL**，不收原始字节，所以先上传到七牛云 OSS 拿 URL。
- **异步 + 轮询**：转写是耗时任务，DashScope 用异步任务模式（提交拿 task_id，再轮询状态），不是一次同步返回。
- **临时文件清理**：`finally: os.unlink(tmp_path)` 保证临时文件不残留。
- **凭证走 `get_effective`**：和 LLM 配置一样支持运行时热配置。

这部分是**完全可选**的——不配 `DASHSCOPE_API_KEY` / 七牛云凭证，系统照常跑（只是录音功能不可用）。

## 4. 可选依赖优雅降级（部署哲学）

SparkOffer 的一个设计主线：**核心功能零外部依赖，增强能力可选且优雅降级**。

| 依赖 | 不配会怎样 | 降级到 |
|---|---|---|
| **Redis** | 自动检测不可用 | 内存 LRU（5000 条）——缓存仍工作，只是不跨进程 |
| **Qdrant** | 连不上 | numpy 向量后端（默认本就是它） |
| **本地 embedding** | 不装 torch 依赖 | API embedding（OpenAI 兼容端点） |
| **ASR/OSS** | 不配凭证 | 录音功能禁用，其余正常 |
| **Reranker** | 不配 | 检索退回原顺序（degraded/off） |
| **多渠道** | 只配单渠道 | 单渠道 + 同渠道重试（无 failover 但能跑） |

> **面试金句**：「我的部署哲学是核心零外部依赖——一个 FastAPI + 一个 SQLite 文件就能跑起来；Redis/Qdrant/本地 embedding/ASR 全是可选增强，连不上自动降级，绝不因为缺个可选组件就启动失败。这让它既能 `docker compose up` 一键起全套，也能在最小环境裸跑。」

**最小启动**（README）：只需配 LLM + Embedding 两组 API，`docker compose up` 或手动 `uvicorn` + `npm run dev` 即可。

## 5. 配置体系（呼应各章）

两层配置，运行时优先：
- **`.env`**（`pydantic-settings` 读）：打底的静态配置。
- **`data/ai_config.json`**（运行时热重载）：优先级更高，可在 Settings 页面热改渠道、换模型，配 `_config_version` 触发单例失效（05 章 §5）。**换渠道不用重启。**

关键环境变量：`API_BASE/API_KEY/MODEL`（LLM）、`EMBEDDING_*`、`RERANKER_*`、`DASHSCOPE_API_KEY`、`QINIU_*`、`REDIS_URL`、`VECTOR_BACKEND/QDRANT_*`、`JWT_SECRET`、`ALLOW_REGISTRATION`。

## 本章小结

- **Docker Compose** 四服务编排：nginx 前端 + uvicorn 后端 + 可选 redis/qdrant；健康检查 + 启动依赖 + 软依赖不阻塞。
- **nginx 流式调优**：`proxy_buffering off` 是 SSE 命门，超时分层（nginx 300s < 后端 360s），HTTP/1.1 长连接；静态资源按哈希激进缓存、index.html 不缓存。
- **ASR**：七牛云 OSS（拿公网 URL）→ DashScope 异步转写 → 轮询，完全可选。
- **可选依赖优雅降级**：核心零外部依赖，Redis/Qdrant/本地 embedding/ASR/reranker/多渠道全部"连不上就降级"——既能一键起全套，也能最小裸跑。
