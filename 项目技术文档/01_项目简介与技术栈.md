# Part 1 · 项目简介与技术栈（简历 / 面试口径）

---

## 一、一句话定位

> **SparkOffer 是一个 AI 驱动的个性化面试训练系统。** 它的内核是一个 **「训练 → 评估 → 画像更新 → 复习调度 → 再出题」的可累积闭环**：每一次答题都被沉淀成跨会话的能力画像，下一轮出题会融合「长期画像 + 领域掌握度 + 知识库 RAG」三层上下文做个性化定题——**练得越多，AI 越懂你**。

技术上它是一个 **复合 Agent 系统**，而不是单一的 RAG 问答：

```
RAG（知识增强）+ LangGraph（状态机编排）+ Mem0 式长期记忆 + Function Calling（工具调用 Agent）
```

---

## 二、解决了什么问题

市面上的面试工具大多是「出题—答题—结束」的一次性问答：题目随机、反馈泛泛、下次再来又从零开始。SparkOffer 解决三件事：

1. **连续性**：训练数据不丢失，沉淀为长期画像（薄弱点、掌握度、思维模式、沟通风格）。
2. **个性化**：出题不是随机抽题，而是融合三层上下文，按掌握度选难度梯度、优先命中历史薄弱点。
3. **闭环复盘**：用**确定性算法**（掌握度公式、SM-2 间隔重复）量化进步，用 **LLM 智能合并**保持画像精炼，再用遗忘曲线安排复习。

## 五、十大创新点（简历口径，逐条可量化、可追溯）

> 下面每条都是「**做了什么 + 为什么这么做 + 关键参数**」的结构，可直接用于简历 bullet 或面试开场。深入原理见 Part 2 对应章节。

### 1. Mem0 风格「两阶段」长期画像更新——避免薄弱点无限堆叠
不是把每次发现的薄弱点 `append` 进画像，而是 **Extract（LLM 提取本次新发现）→ Update（LLM 看「已有画像 + 新发现」决定每条做 ADD / UPDATE / NOOP / IMPROVE）** 两阶段。LLM 解析失败时**降级到向量余弦去重**（阈值 0.75）。这样几十次训练后画像仍精炼，而非几百条重复条目。
`memory.py:622-787`（`llm_update_profile` / `_apply_memory_ops` / `_deterministic_update`）

### 2. 自研轻量向量检索——百级数据规模刻意不上 Milvus
长期记忆的 embedding 存为 SQLite BLOB，用 numpy 做**矩阵化余弦 + argmax**（不是 N 次 reshape 循环）。叠加 **14 天半衰期的指数时间衰减**（最多削 30% 权重），让"近期洞察"优先；单用户上限 500 条，超限自动清理最旧。可插拔后端（裸 uvicorn 默认 numpy / Docker 部署默认 Qdrant 单 collection 多租户）。
`vector_memory.py:240-421`、`vector_store/`

### 3. 确定性掌握度算法 + SM-2 间隔重复——量化进步不靠 LLM 主观打分
掌握度走**确定性公式**：`contribution = (难度/5) × (得分/10) × 100`，再用 **EWMA**（`0.7×旧 + 0.3×新`）平滑；薄弱点用 **SM-2** 排复习（答对间隔拉长 1→3→`interval×ease`，答错重置 1 天）。**自定义毕业机制**：连续 3 次 ≥7 分才"毕业"（不用 SM-2 原生 repetitions，因为它把 6 分也算通过）。
`spaced_repetition.py:13-152`

### 4. LangGraph 状态机 + 隐藏 EVAL 标记 + 三重护栏——让面试"自然推进"且不死循环
简历模拟面试是 5 阶段状态机（开场→自我介绍→技术→项目深挖→反问）。面试官在每条回复末尾输出隐藏的 `<!--EVAL:{...}-->` 自评 JSON，条件边据此决定是否进入下一阶段。三重护栏：**硬上限**（每阶段≤10 题）→ **eval 驱动**（≥2 题且 `should_advance`）→ **计数兜底**（≥`max_questions_per_phase`）。配 `interrupt_before=["wait"]` 实现人在环，`SqliteSaver` 持久化状态、**重启可续接**。
`graphs/resume_interview.py:46-287`、`graphs/checkpointer.py`

### 5. 多渠道 LLM 自动 failover + 三态熔断器——生产级鲁棒性
`ResilientChatModel` 是 `ChatOpenAI` 的 drop-in 替换：**同渠道先重试**（瞬时 5xx/429/超时，2 次、1.5s 退避）→ 失败才切下一渠道；**致命 4xx（400/401/403/404/422）直接抛**不浪费冷却。流式做**两阶段 failover**：首 chunk 前可切渠道，首 chunk 已吐出后**禁止切换**（否则会把新答案拼接到半截答案上）。渠道层：优先级排序 + **Key 轮询** + 3 错 60s 冷却 + **HALF_OPEN 探活**。Embedding 侧独立的**三态熔断器**（CLOSED/OPEN/HALF_OPEN，5 错开路、60s 后探活、2 次成功才闭合）。
`llm_provider.py:162-287`、`channel_manager.py`、`embedding_tasks.py:31-128`

### 6. RRF 多路召回 + 语义去重 + Cross-Encoder 重排——RAG 检索做到"可观测、可降级"
出题前对 **每个薄弱点各发一路检索**（并发），用 **RRF 倒数排名融合**（`score=Σ1/(k+rank)`，k=60）合并——比"把 5 个薄弱点拼成一个 query"语义信号强得多。再用 **余弦 ≥0.85 去重**段落复述，可选 **Cross-Encoder 重排**（applied/degraded/off 三态、graceful 降级）。每一步 embedding 走 Redis 缓存，并发限到 2 避开上游 per-key 限流。
`graphs/rag_retrieval.py`、`reranker.py`

### 7. 分阶段流式出题管道——把"30 秒黑屏"变成"3 秒见首题"
出题被拆成 5 个**逐阶段计时**的 stage（prepare→retrieve→generate→validate→finalize），每个阶段推 `pipeline_stage` SSE 事件，前端渲染实时时间线、一眼看出瓶颈。生成阶段用**增量 JSON 解析**（括号深度状态机），LLM 边吐 token 边逐题渲染；配 **种子题池**（先秒出 6 道命中薄弱点的题，只让 LLM 补剩余）进一步压首屏延迟。
`graphs/drill_pipeline.py`、`utils/stream_parser.py`、`graphs/seed_pool.py`

### 8. Token 预算上下文装配器——告别 `[:5000]` 魔法数硬截断
统一的 `ContextBudget`：先用 tiktoken（`cl100k_base`，缺失时 CJK 感知启发式）测模板固定开销，再把剩余预算**按优先级贪心分配**给知识/最近题/历史洞察，放不下就按行边界截断或整段丢弃，并产出 token 报告供观测。窗口取**所有启用渠道里最小的 context_window**（failover 可能落到最紧的渠道）。
`context_assembler.py`

### 9. Reasoning-aware SSE 心跳——根治"思考模型把流式拖到超时"
推理模型（gpt-5.x / o-系 / DeepSeek-R1）在思考阶段会持续吐**空 content** 的 chunk，裸 `astream` 既不触发 token 也不触发 idle，流会"字节静默"直到 nginx/httpx 超时→白屏。`iter_llm_stream` 统一处理：把思考增量从 `additional_kwargs` 里抠出来按 ~3s 批量转发，30s 无任何输出推 `ping`，read 超时设 360s（**故意高于** nginx 300s，让超时只由一层兜）。
`utils/sse_helpers.py`、`llm_provider.py:20-26`

### 10. 离线评测矩阵 + 在线 RAG 指标——"先修尺子，再谈优化"
离线：**5 persona × 3 strategy × 4 judge** 矩阵，judge 含确定性的 coverage / **difficulty_kl（KL 散度）** / diversity，以及 **LLM-as-Judge 多模型投票**（最多 3 个不同渠道 1-10 打分取中位）；用 random/topic_only 做基线证明"个性化优于基线"这个**相对结论**成立。在线：出题时实时算检索 relevance/coverage/diversity 落库，前端 RAG Dashboard 可视化。**所有 judge fail-soft**，embedding 挂了给低分+诊断而非抛异常。
`backend/eval/`、`rag_metrics.py`

> 另有一批"加分项"：知识自进化（高分答案沉淀进知识库、低分题进高频库，增量入向量索引）、k-NN 难度锚点校准（用离线锚点纠正 LLM 自报难度）、QA Arena 上下文压缩（增量滚动摘要 + map-reduce）、配置热重载（换 embedding 渠道自动失效相关单例与维度缓存）。详见 Part 2。

## 七、面试红线（避免自己挖坑）

1. **别把它说成"RAG 应用"**——它是 `RAG + LangGraph + Memory + Function Calling` 的复合 Agent，RAG 只是三层上下文之一。
2. **别说"多 Agent 协作"**——项目里**没有** multi-agent；浮窗助手是单 Agent + Tool Use，简历面试是 State Machine。诚实说"目前单 Agent，但理解 ReAct/AutoGen/CrewAI 的差异"。
3. **别说"用了 Milvus/Pinecone"**——自研 SQLite+numpy 是刻意选型，是亮点不是短板。
4. **别把画像说成"会自己学习的 ML 模型"**——本质是 LLM 提示工程 + 确定性算法（掌握度公式、SM-2），没有任何 fine-tuning。
5. **别说"全异步"**——LlamaIndex 检索是同步的，用 `asyncio.to_thread` + `wait_for` 超时兜底，诚实说"混合同步异步，关键路径有 timeout"。
6. **掌握度被质疑"LLM 打分不靠谱"时不要慌**——掌握度是**确定性公式**，不依赖 LLM 主观分；只有画像合并才用 LLM。
